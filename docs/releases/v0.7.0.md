# rvc v0.7.0 — fail-closed slashing & doppelganger enforcement, KAT-anchored Electra/Deneb block roots, and a workspace-wide refactoring program

**Release date:** 2026-07-28
**Target tag:** `v0.7.0` on the same commit for `bin/rvc`, `bin/rvc-signer`, and `bin/rvc-keygen`.

This release lands the remediation of the 2026-07-18 security review plus a
six-phase workspace refactoring program (Themes A–H). The headline changes are
**fail-closed slashing-DB startup** (a missing or corrupt database now refuses
to start instead of silently creating a fresh one), **doppelganger protection
enforced in the production signing path** (a per-slot liveness loop drives
`ForwardWindowMachine`, and every duty consults the enablement gate before the
slashing stage), **a persistent keymanager deletion denylist** (deleted keys
can no longer resurrect on restart), and **typed Electra/Deneb SSZ block
bodies** so proposal signing roots are computed from the real body
`hash_tree_root` and verified against external `remerkleable` known-answer
vectors. All three binaries must be upgraded together.

> **Scope.** 182 commits on `develop` since `v0.6.0` (`v0.6.0..develop`).
> `develop` is built directly on top of the `v0.6.0` release commit, so
> everything below is new relative to a `v0.6.0`-class build. If you are
> upgrading from an older release, also read the prior `docs/releases/vX.Y.Z.md`
> files and apply their operator actions.

## Breaking changes for operators

### Missing or corrupt slashing DB now refuses to start (`a29068f`)

Both `rvc` and `rvc-signer` previously created a fresh, empty slashing database
when the configured path did not exist — which silently discards your signing
history if the path is wrong (new host, typo'd mount, lost volume) and exposes
you to slashing. Now:

- A **missing** DB path is a fatal startup error unless you explicitly opt in
  with `--init-slashing-db` (or `allow_fresh_db = true` in the `rvc` config).
- **0-byte and corrupt-header** files are rejected always — they are never
  wiped or re-created, opt-in or not.
- Intentional fresh initialization logs a loud warning; the opt-in never
  overwrites a non-empty database.

**Action required:** on the *first* deployment of a brand-new validator host
(and only then), pass `--init-slashing-db` once. Existing hosts need no flag —
but if v0.7.0 fails to start where v0.6.0 started "fine", treat it as the
guard working: verify your `slashing_db_path` points at the real history
before overriding. `rvc slashing prune` (new, below) shares the same
never-create policy.

### `rvc-signer --password-dir` is gone; a password source is required (`e347751`)

The `--password-dir` flag and config field never functioned and have been
removed. `rvc-signer` now **fails at startup** when no keystore password file
is configured instead of silently trying an empty password. **Action
required:** if your unit files pass `--password-dir`, switch to the password
file option before upgrading.

### v1 signer gRPC proto retired (`61cdd8e`, `9a66b75`)

`signer.proto` (v1) is no longer compiled into the server or the client crate;
only the `signer.v2` gRPC surface remains. The v1 stubs were `Unimplemented`
placeholders, so any client that still worked was already on v2 — but if you
have out-of-tree tooling generated from the v1 proto, regenerate it from
`signer.v2.proto`. Relatedly, DVT peer fan-out now dials the **v2**
`PartialSign` RPCs (`d6e8869`) — multi-peer DVT signing previously hit the
unimplemented v1 surface.

### Unsupported fork mismatch is fatal at startup (`40b6c1e`)

If the beacon node reports a fork the binary does not support, `rvc` now exits
at startup instead of running with degraded assumptions. Override (at your own
risk, e.g. mid-upgrade on a devnet) with `--allow-unsupported-fork`.

### Watermark equality now blocks on the production path (`7038646`, `40b6c1e`)

EIP-3076 minimal-interchange semantics require refusing to sign **at** the
recorded watermark, not just below it. The production `stage_block` /
`stage_attestation` paths now use `<=` for block-slot and attestation-target
watermark checks. After importing an interchange file, the first proposal or
attestation at exactly the imported maximum is refused — this is correct,
conservative behavior (the next slot/epoch proceeds normally).

### Signature-affecting fixes on non-mainnet networks

Three fixes change which bytes are signed in specific non-mainnet or
previously-broken paths. On mainnet defaults, signatures are unchanged.

- **Builder registration uses network genesis on all transports** (`9ecdb46`):
  `VALIDATOR_REGISTRATION` derives the application-builder domain from the
  server's configured `--network` genesis fork version on both gRPC and HTTP.
  Previously HTTP always used mainnet while gRPC accepted a per-request
  override, so identical non-mainnet registrations produced different
  signatures across transports. On Hoodi/Holesky/Sepolia, set `--network` to
  match the chain; a gRPC request fork field, when present, must equal the
  server network.
- **`grpc-signer` fork tagging follows the network schedule** (`a72f687`):
  `SignContext` now carries a resolved `ForkName`; the silent "unknown version
  ⇒ Deneb" fallback is gone. Non-mainnet SSZ fork tagging is now correct
  (e.g. Hoodi Electra is fork id 5, not 4); unknown versions fail with a typed
  error.
- **`rvc-keygen` BLS-to-execution changes sign with the genesis fork version**
  (`0fa0a42`): per EIP-7044, `DOMAIN_BLS_TO_EXECUTION_CHANGE` uses
  `GENESIS_FORK_VERSION`, not the Capella fork version. Messages produced by
  older builds for non-mainnet chains may not verify; regenerate them.

### Web3Signer *client* requests are now spec-compliant (`424a1a7`)

When `rvc` uses an external Web3Signer as its remote signer, it previously
sent a bare `signing_root` JSON body that real Web3Signer deployments reject.
It now sends type-tagged camelCase payloads per the remote-signing API;
unsupported types return a typed error instead of a malformed request. If you
had a proxy or shim tolerating the old body, it is no longer needed. (The
server-side HTTP API shipped in v0.6.0 is unaffected.)

## Behavior changes

### Doppelganger protection is now enforced in production signing (`dee059b`, `16ba7fb`, `0200aab`)

The doppelganger `ForwardWindowMachine` is constructed at startup, registered
for both boot-loaded and API-imported keys, and driven by a per-slot loop that
observes validator liveness through the `bn-manager` failover pool. Every
`SignerService` duty path consults `SigningEnablement` **before** the slashing
stage; the gate is fail-closed by default, and slashable paths re-check under
the per-validator lock. Practical effect: after startup or key import, a key
does not sign until its forward window clears — expect the documented
detection delay before first duties, and a hard stop if a doppelganger is
detected. Keymanager `DELETE` cancels monitoring; stopping monitoring no
longer silently disables the machine. Restart-skip decisions come from a
single `MonotonicEpochClock`, and a future-dated `last_signed` is treated as
safe-skip (`e1c3f36`).

### Deleted keys stay deleted across restarts (`6d77dad`, `e0b06e0`)

Keymanager deletions are recorded in a `.rvc.deleted_keys` denylist file
(`0o600`) written *before* registry removal, and honored by keystore-dir load,
secret-provider `load_all`, live refresh, and the CLI exit paths — closing the
RockLogic-style "deleted validator resurrects on restart" hazard.
`list`/`delete`/`has_key` now operate on the real local signing registry
(boot-loaded + dynamically imported), `DELETE` removes boot keys from the live
signer, unlinks canonical and non-canonical keystore files, and returns honest
per-key status plus the EIP-3076 export. Re-import clears the denylist entry
only after a successful add.

### Slashing protection: import watermarks, prune CLI, faster stage path

- **Interchange import raises watermarks** (`c905078`): per-pubkey block and
  attestation watermarks are set from imported history maxima in the same
  transaction, so a restored validator cannot re-sign at or below the imported
  floor even if individual history rows are later pruned.
- **New `rvc slashing prune` subcommand** (`25b78d6`): watermark-based pruning
  of history rows with `--dry-run` and `--yes`, an actionable error when no
  watermarks are set, and the same refuse-to-create-a-fresh-DB policy as
  startup.
- **Targeted SQL on the hot path** (`e6903e8`): staging an attestation now
  runs indexed, targeted queries instead of a full history scan, with the
  full-scan implementation kept as a property-tested oracle.
- **GVR encoding no longer blocks interchange import** (`3c3cf59`,
  `e8d218c`): `genesis_validators_root` metadata is compared by decoded bytes,
  so interchange files that differ only by `0x`-prefix or hex case now import;
  stored rows are canonicalized to `0x`+lowercase. All-zeros GVR is still
  rejected.
- The pure EIP-3076 rules now live in one module behind a history seam
  (`0291b86`), the second rule implementation is gone (`45bd08b`,
  `fbdd708`), and the full EIP-3076 conformance and property suites run
  against the production stage path (`9a80500`, `95505f5`, `e59f965`).

### Proposal block roots are typed-SSZ and KAT-anchored (`f9b5962`, `2493c3a`, `5505748`)

`eth-types` gained hand-typed Electra and Deneb `BeaconBlockBody` /
`BlindedBeaconBlockBody` containers (SSZ decode + `tree_hash`), and
`compute_block_root` / `compute_blinded_block_root` now decode the body and
use its real `hash_tree_root` as the body leaf — matching external
`remerkleable` known-answer vectors for every fork/variant. Proposal signing
paths take `Result` roots, so a malformed body is a typed error instead of a
panic or a wrong root. Supporting changes:

- Corrupt block bodies no longer fingerprint as *empty blob KZG commitments*:
  `extract_blob_kzg_commitments` and the `BlockContents`/`BeaconBlock`
  accessors return `Result` and decode through the typed containers
  (`1cd560c`). A genuinely empty list is still `Ok([])`.
- Electra-shaped attestation SSZ buffers are rejected with a typed error
  instead of a generic phase0 decode failure (`4db0662`).
- A **KAT-first CI policy** (`930a121`, `crates/architecture-tests`) now fails
  any `*_root`/`*tree_hash*` test that asserts only self-consistency without a
  known-answer constant or a documented exemption.

### Reliability: proposer failover, resilient key loading, atomic reload

- **Block production honors multi-node failover** (`2f1ef37`): with more than
  one `proposer_nodes` endpoint, production routes through the proposer
  `BnManager` pool (best-of/failover) instead of always using
  `proposer_nodes[0]`. Empty `proposer_nodes` behavior is unchanged.
- **Secret-provider loading survives one bad provider** (`40b6c1e`,
  `147443b`): startup continues past a failing provider by default (opt into
  the old all-or-nothing with `--secret-provider-strict`); boot and refresh
  share one instrumented fetch pipeline with denylist checks, bounded
  concurrency, and per-fetch timeouts — and a refresh failure no longer wipes
  the loaded-keys gauge.
- **Validator-store config reload is atomic** (`25a99e7`): defaults and
  per-validator overrides live under a single lock, removing a reload/read
  deadlock and torn-read window.
- **Beacon HTTP hardening** (`b6a7f30`, `1ae3211`): four retry loops collapsed
  into one engine with shared backoff/429/5xx policy; URL building
  percent-encodes path segments and pins the origin against host-takeover;
  duty caches share constructors and key rotation clears every duty layer
  (`a4f7088`).

### Config: typed enums, nested groups, CLI-over-file precedence

- **Invalid config enum values fail at load** (`4ccaf6a`):
  `slashed_validators_action`, `broadcast` topics, `tracing_exporter`, and
  beacon-node `roles` deserialize as typed enums; a typo now fails at startup
  with an error naming the field/variant instead of being warned-and-defaulted.
  Accepted spellings are unchanged.
- **Nested config groups with flat-key aliases** (`1d36de2`, `601d3da`): the
  TOML schema is now grouped into sub-structs, but every legacy flat key is
  still accepted as an alias — no config rewrite required.
- **`rvc-signer` CLI flags always beat the config file** (`55681da`): an
  explicitly passed flag whose value equals the built-in default (e.g.
  `--network mainnet`) is no longer overridden by `config.toml`. Unpassed
  flags still fall back to file, then default. Affected flags include
  `--listen-address`, `--backend`, `--reload-interval`,
  `--http-listen-address`, `--http-tls-mode`, `--network`, and `--dvt-timeout`.
- **OTEL sample-rate precedence fixed** (`67e023c`): an explicit CLI sample
  rate is no longer overridden by environment defaults.

### Piped console logs are now plain text (`cc6b844`)

The pretty console layer enables ANSI color/styling only when stdout is a
terminal. Logs redirected to journald, docker, files, or any pipe no longer
contain escape sequences; interactive terminal output is unchanged. If you had
an ANSI-stripping step in a log pipeline it is now redundant (but harmless).

### `rvc-keygen` never silently overwrites signed outputs (`08fd25b`)

Exit and BLS-to-execution outputs are written with `create_new` semantics on
**all** platforms (previously non-unix used plain `fs::write` and could
overwrite). Writes to an existing path fail with a path-bearing error; unix
permissions remain `0o600`.

## New: `rvc-signer` client-CN allow-list (`05a5664`)

`--allowed-client-cns <path>` restricts the primary gRPC `SignerService` and
the shared HTTP Web3Signer path to a listed set of TLS client CNs; non-listed
(including unknown) CNs are rejected **before** signing. Unset, the signer
logs a startup warning and accepts any CN — mTLS itself remains mandatory
either way. The DVT peer allow-list is a separate, unchanged mechanism.

## Signing core: one engine across gRPC, HTTP, and DVT

The signer stack was consolidated so every transport shares one
domain/signing-root/slashing decision path — removing the class of
cross-transport drift bugs the builder-registration fix exemplifies:

- **Transport-neutral `SignPlan` engine** (`819789c`): `plan_sign`
  single-sources domain computation, signing roots, and slashable policy for
  gRPC, HTTP, and DVT; aggregate tree-hashing is fail-closed.
- **Shared slashable core with explicit timeout policy** (`5976190`,
  `074e03a`): stage/sign/commit with Discard-vs-Retain on timeout — a remote
  backend that times out *retains* staged history (so a late completion cannot
  double-sign), while unambiguous local rejections are discarded.
- **`SlashingBlocked` vs `CommitFailed`** (`28e5768`): stage rejections and
  post-sign commit I/O failures are distinct errors; commit failures carry the
  signing root for same-root retry.
- **One gate-error taxonomy** (`3aa9fc8`): both transports map gate errors
  through a shared `classify()` to matching status codes, sanitized client
  messages, and metrics labels; all ten v2 gRPC handlers record metrics
  through one helper (`03b75e3`).
- **Shared wire/proto crates**: `rvc-web3signer-wire` (`b410400`) is the
  single Serialize+Deserialize Web3Signer request-type set consumed by both
  the client (`35234fe`) and server (`a70195a`); `rvc-signer-proto`
  (`feb9231`) compiles `signer.v2.proto` once for client and server.
- **Fork/network single-sourcing**: a `NetworkPreset` table
  (mainnet/hoodi/holesky/sepolia) with typed fork versions and GVR
  (`cf12148`) now backs keygen, the validator client (`399b591`), and fork
  identity/layout lookups via `ForkName` (`5dcddab`, `9cc41c7`); signing-root
  computation flows through shared fork-aware helpers with the EIP-7044
  Capella cap applied only to voluntary exits (`b64aa5f`, `0fbe30c`).
- Keystore robustness: a wrong-length AES-128-CTR IV in a keystore is a typed
  per-item error instead of a panic (`4d679c8`).

## Workspace restructuring and hygiene

A six-phase refactoring program (`plan/` Themes A–H) restructured the
workspace without changing external behavior beyond what is listed above:

- **New crates**: `signer-server` (the `rvc-signer` server assembly as a
  library; `bin/rvc-signer` is now a CLI shim — `a3f2034`),
  `rvc-observability` (logging/hex/redaction leaf extracted from `crypto` —
  `e24a284`), `rvc-signer-proto`, `rvc-web3signer-wire`, and a
  `publish = false` `rvc-test-support` PKI/mTLS test harness (`1840945`).
  The standalone `rvc-propagator` crate folded into `bn-manager` (`0eafc89`);
  `sync-service` shrank to aggregator helpers with sync-committee constants
  re-homed in `eth-types` (`5987a7d`, `c56ecfc`).
- **`rvc` startup is now a library bootstrap pipeline**: `open_slashing_db` →
  `connect_beacon` → `load_signing_keys` → `wire_signing_enablement` →
  `build_services` → keymanager/slashing-monitor spawns → `bootstrap::run`
  (`bcd0af0` … `e2c9904`), with `bin/rvc` reduced to CLI parse plus one call.
- **`unsafe_code = "deny"` workspace-wide** (`eafc2ca`) with a reviewed,
  justified allow-list; the one unsound test downcast was removed (`d266ce0`).
- **Dead code purged** (Theme B): generation-one `is_safe_to_sign` APIs, the
  `SyncService` twin stack, `ServiceBuilder::build_all`, `AttestationTimer`,
  the `eth-types` insecure-gate twin, and the unused BN selection strategy are
  gone; seed-only test helpers are now named `seed_*` and documented as
  bypassing EIP-3076 (`0faa7c5`).
- **Architecture enforcement**: `ARCHITECTURE.md` is generated from `cargo
  metadata` and CI fails on divergence (`597e05b`); domain→domain edges are
  forbidden with an explicit grandfather list (`ef71408`); the KAT-first root
  policy gate (`930a121`) runs alongside.
- **Dependency hygiene & supply chain** (`cf98bcb`, `a7f8cdf`):
  `rustls-webpki` bumped past the CRL/name-constraint advisories, `cargo
  audit` now runs in CI with justified ignores, unused deps dropped, shared
  deps promoted to `workspace.dependencies`. `RVC_ALLOW_NON_WAL_SLASHING_DB`
  and keystore/slashing path-divergence footguns are documented, with a
  startup warning when those paths land on different filesystems.
- **Performance**: `PubkeyMap` keyed by `[u8; 48]` BLS bytes with one shared
  pubkey↔validator-index registry (O(validators) duty-cache access,
  `bc50ea8`); slashing stage path uses targeted SQL (`e6903e8`); BN health
  writes batched per selection round (`848c320`).
- **Tests**: bin-tier suites re-homed into library crates; hermetic
  CARGO_BIN_EXE smoke tests for both binaries against a wiremock BN
  (startup/health/SIGTERM, `a678888`, `3a6a375`, `5d60720`); shared
  `MockBeaconNodeClient` behind role traits replaced hand-rolled mocks
  (`c2a9e62` and follow-ons); an end-to-end test proves key import clears
  duty caches and stays gated until the doppelganger window clears
  (`5c1dea0`); pipeline-level double-vote rejection and slashing-DB
  fail-closed guards (`afd55b7`).

## Upgrade path from v0.6.0

1. Stop `rvc`, `rvc-signer`, and any `rvc-keygen` jobs.
2. Replace all three binaries from the same `v0.7.0` build — they must be
   upgraded together.
3. **Slashing DB**: no schema change, existing databases open in place. Do
   **not** pass `--init-slashing-db` on an existing host. If startup now fails
   where v0.6.0 started, verify the configured `slashing_db_path` points at
   the real history before overriding — the new guard exists precisely for
   that misconfiguration.
4. **`rvc-signer` units**: remove any `--password-dir` usage (startup now
   fails without a configured password file). If you run non-mainnet chains,
   confirm `--network` matches — builder-registration and fork-tagging
   signatures now derive from it on every transport.
5. **Doppelganger**: expect the forward-window delay before first duties after
   startup or key import; this is the fail-closed gate working. The
   `--no-doppelganger-detection` opt-out is unchanged.
6. **Optional hardening**: add `--allowed-client-cns <file>` on `rvc-signer`
   to pin client CNs (a startup warning reminds you while it is unset);
   consider `--secret-provider-strict` if you prefer all-or-nothing key
   loading; use the new `rvc slashing prune --dry-run` to inspect prunable
   history.
7. Config files need no rewrite: nested groups accept all legacy flat keys,
   but note the typed-enum validation — a previously warned-and-ignored typo
   in `tracing_exporter`, `broadcast`, `slashed_validators_action`, or BN
   `roles` is now a startup error.
8. Restart `rvc-signer`, then `rvc`.
